# Study02_ToDoList

하루치 할 일을 날짜별로 적고, 하나씩 지워 나가며 얼마나 했는지 확인하는 개인용 할 일 관리 앱이다. 할 일은 업무·개인·공부로 나뉘고, 못 끝낸 일은 버튼 하나로 오늘 목록에 옮겨 온다.

**바로 써 보기: https://asy0528.github.io/Study02_ToDoList/**

`index.html` 하나를 브라우저로 열면 바로 돌아간다. 가입, 서버, 설치 과정이 없고 적은 내용은 그 브라우저의 localStorage에 저장된다.

## 진행 상황

| 단계 | 상태 |
|---|---|
| 요구사항 정리 (PRD) | 완료 |
| 구현 프롬프트 ([PROMPTS.md](PROMPTS.md)) | 완료 |
| 구현 (`index.html`) | 완료 |
| 완료 기준 확인 (PRD 10장 1~8) | 완료 |
| 배포 (GitHub Pages) | 완료 |

PRD의 기능 F-1 ~ F-9가 모두 들어가 있다.

## 무엇을 할 수 있나

- 할 일 추가 · 수정 · 삭제 (방금 추가한 할 일이 맨 위)
- 완료 체크와 진행률 막대 (보고 있는 날짜와 필터 기준)
- 업무 / 개인 / 공부 카테고리와 필터 탭
- 날짜 이동 (◀ ▶ · 오늘)
- 지난 날짜의 미완료 항목을 오늘로 옮기기
- 새로고침이나 브라우저 재시작 후에도 그대로 남는 저장

## 화면

- **넓은 화면 (900px 이상):** 왼쪽 사이드바에 날짜, 진행률, 입력줄, 필터가 있고 오른쪽에 목록이 있다. 목록을 스크롤해도 사이드바는 제자리에 있다.
- **좁은 화면:** 위에서 아래로 한 줄로 쌓인다. 폭 360px까지 가로 스크롤 없이 보인다.
- **색:** 강조색은 파랑이다. 카테고리 배지는 색을 채운 바탕에 흰 글자로, 업무는 파랑, 개인은 초록, 공부는 주황이다. 선택한 필터 탭과 진행률 막대도 파랑이다.

기능별 세부 규칙, 화면 구성, 데이터 형식, 완료 기준은 [PRD.md](PRD.md)에 정리했다.

## 만드는 방식

- HTML, CSS, 순수 자바스크립트
- 외부 라이브러리 · 프레임워크 · 빌드 도구 없음
- 파일은 `index.html` 하나. 스타일과 스크립트를 같은 파일 안에 둔다
- ES 모듈을 쓰지 않는다. 파일을 더블클릭해 열면(`file://`) 모듈을 불러올 수 없기 때문이다

## 써 보는 방법

- **웹에서:** https://asy0528.github.io/Study02_ToDoList/ 를 연다. `main` 브랜치의 `index.html`이 GitHub Pages로 배포되어 있다.
- **내 컴퓨터에서:** `index.html`을 내려받아 더블클릭한다. 인터넷 연결도 필요 없다.

데이터는 브라우저마다, 그리고 웹 주소와 내 컴퓨터 파일마다 따로 저장된다. `asy0528.github.io` 아래의 다른 프로젝트와는 저장 공간을 함께 쓰지만, 저장 키를 `todoApp.v1`로 따로 두어 섞이지 않는다. 다른 브라우저나 다른 PC에서 열면 빈 목록으로 시작하고, 브라우저의 사이트 데이터를 지우면 할 일도 함께 지워진다.

## 저장소 구성

```
Study02_ToDoList/
├── index.html                                    # 앱 (HTML·CSS·JS 한 파일)
├── README.md
├── README-v1.md                                  # PRD 작성 시점의 README
├── README-v2.md                                  # 구현 프롬프트 작성 시점의 README
├── README-v3.md                                  # 구현 완료 시점(배포 전)의 README
├── PRD.md                                        # 요구사항, 화면, 데이터, 완료 기준
└── PROMPTS.md                                    # Claude Code용 5단계 구현 프롬프트
```

## 이 프로젝트에 대해

AI 코딩 도구로 앱을 만드는 과정을 익히기 위한 두 번째 실습이다. Claude Code에 [Superpowers](https://github.com/obra/superpowers) 플러그인을 붙여, 질문에 답하며 요구사항을 좁히고(brainstorming) 그 결과를 PRD로 남겼다. 그다음 `writing-plans` 스킬로 PRD를 5단계 구현 프롬프트([PROMPTS.md](PROMPTS.md))로 나누고, 단계마다 테스트를 먼저 쓰고 구현하는 방식으로 앱을 완성했다.
