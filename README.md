# Study02_ToDoList

하루치 할 일을 날짜별로 적고, 하나씩 지워 나가며 얼마나 했는지 확인하는 개인용 할 일 관리 앱이다. 할 일은 업무·개인·공부로 나뉘고, 못 끝낸 일은 버튼 하나로 오늘 목록에 옮겨 온다.

**바로 써 보기:** [기본 버전](https://asy0528.github.io/Study02_ToDoList/) · [모바일 버전](https://asy0528.github.io/Study02_ToDoList/mobile/) (자세한 내용은 아래 [실행](#실행) 절)

`index.html` 하나를 브라우저로 열면 바로 돌아간다. 가입, 서버, 설치 과정이 없고 적은 내용은 그 브라우저의 localStorage에 저장된다.

## 진행 상황

| 단계 | 상태 |
|---|---|
| 요구사항 정리 (PRD) | 완료 |
| 구현 프롬프트 ([PROMPTS.md](PROMPTS.md)) | 완료 |
| 구현 (`index.html`) | 완료 |
| 완료 기준 확인 (PRD 10장 1~8) | 완료 |
| 배포 (GitHub Pages) | 완료 |

| 데스크톱 화면 정리와 모바일 버전 분리 (`mobile/`) | 완료 |

PRD의 기능 F-1 ~ F-9가 모두 들어가 있다.

## 무엇을 할 수 있나

### 할 일
- 입력창에 적고 Enter 또는 [추가]로 등록한다. 방금 추가한 할 일이 목록 **맨 위**에 온다.
- 카테고리(업무 / 개인 / 공부)를 골라 등록한다. 고른 카테고리는 다음 입력에도 유지된다.
- 비어 있거나 공백만 있는 내용은 등록되지 않는다.
- 체크박스로 완료 표시를 한다. 완료한 항목은 취소선과 흐린 글자로 바뀌고 목록에는 남는다.
- [수정]을 누르면 그 줄에서 바로 내용과 카테고리를 고친다. Enter는 저장, Esc는 취소다.
  - 편집 중인 줄의 체크박스는 잠긴다.
  - 편집 중에 다른 줄을 체크해도 입력하던 내용은 그대로 남는다.
  - 한글을 입력하다 누른 Enter도 마지막 글자까지 한 번만 저장된다.
- [삭제]를 누르면 "이 할 일을 삭제할까요?"라고 한 번 더 묻는다.

### 진행률
- 파란 막대와 그 아래 `완료 수 / 전체 수 (퍼센트)`로 보여 준다.
- 체크할 때마다 막대가 차오르고, 체크를 풀면 줄어든다.
- 할 일을 추가하면 전체 개수가 늘어 막대가 그만큼 짧아지고, 삭제하면 다시 계산된다.

  | 한 일 | 표시 |
  |---|---|
  | 할 일 4개 추가 | `0 / 4 (0%)`, 막대 비어 있음 |
  | 1개 체크 | `1 / 4 (25%)`, 막대 4분의 1 |
  | 1개 더 체크 | `2 / 4 (50%)`, 막대 절반 |
  | 할 일 1개 더 추가 | `2 / 5 (40%)`, 막대 40% |

- 계산 기준은 **보고 있는 날짜 + 선택한 필터 탭**이다. 업무 탭을 보면 업무 항목만으로, 어제로 가면 어제 할 일로 다시 계산한다. 그래서 화면에 보이는 목록과 숫자가 항상 맞는다.

### 카테고리와 필터
- [전체] [업무] [개인] [공부] 탭으로 해당 할 일만 본다.
- 앱을 다시 열면 항상 [전체]부터 보인다.

### 날짜
- ◀ / ▶로 하루씩 이동하고, [오늘]로 돌아온다.
- 지난 날짜를 보면 아직 못 끝낸 할 일에만 [오늘로] 버튼이 생긴다. 누르면 그 할 일이 오늘 목록으로 옮겨진다.
- 할 일이 없는 날짜나 카테고리에서는 안내 문구가 나온다.

### 저장
- 바뀔 때마다 자동으로 저장된다. 새로고침하거나 브라우저를 껐다 켜도 그대로 남는다.

## 화면

- **넓은 화면 (900px 이상):** 왼쪽에 흰 카드 모양의 사이드바(제목, 날짜, 진행률, 입력줄, 필터)가 있고 오른쪽에 목록이 있다. 목록을 스크롤해도 사이드바는 제자리에 있다. 사이드바에서는 입력창, 카테고리 선택, [추가]가 세로로 쌓이고, 목록 줄은 좁은 화면보다 여유 있게 띄운다.
- **좁은 화면:** 위에서 아래로 한 줄로 쌓인다. 폭 360px까지 가로 스크롤 없이 보인다.
- **모바일 버전 (`mobile/`):** 넓은 화면에서도 2단으로 바뀌지 않고 항상 한 줄로 보인다. 휴대폰에 맞춘 화면을 데스크톱에서 그대로 보고 싶을 때 쓴다.
- **색:** 강조색은 파랑이다. 카테고리 배지는 색을 채운 바탕에 흰 글자로, 업무는 파랑, 개인은 초록, 공부는 주황이다. 선택한 필터 탭(알약 모양), [추가] 버튼, 진행률 막대도 파랑이다.
- **키보드:** 마우스 없이 Tab, Enter, Space, Esc로 모두 쓸 수 있다. 체크하거나 저장한 뒤에도 키보드 위치(포커스)가 그 줄에 남는다.

기능별 세부 규칙, 화면 구성, 데이터 형식, 완료 기준은 [PRD.md](PRD.md)에 정리했다.

## 만드는 방식

- HTML, CSS, 순수 자바스크립트
- 외부 라이브러리 · 프레임워크 · 빌드 도구 없음
- 파일은 `index.html` 하나. 스타일과 스크립트를 같은 파일 안에 둔다
- ES 모듈을 쓰지 않는다. 파일을 더블클릭해 열면(`file://`) 모듈을 불러올 수 없기 때문이다

## 실행

| 버전 | 웹에서 열기 | 내 컴퓨터에서 열기 | 화면 |
|---|---|---|---|
| 기본 | https://asy0528.github.io/Study02_ToDoList/ | `index.html` 더블클릭 | 넓은 화면(900px 이상)은 사이드바 + 목록 2단, 좁은 화면은 한 줄 |
| 모바일 | https://asy0528.github.io/Study02_ToDoList/mobile/ | `mobile/index.html` 더블클릭 | 화면 폭과 상관없이 항상 한 줄 |

웹 주소는 `main` 브랜치를 GitHub Pages로 배포한 것이다. 내 컴퓨터에서 열 때는 설치도 인터넷 연결도 필요 없다.

### 두 파일은 무엇이 같고 무엇이 다른가

| 부분 | 기본 `index.html` | 모바일 `mobile/index.html` |
|---|---|---|
| 기능 코드 (`<script>`) | 같음 | 같음 (한 글자도 다르지 않다) |
| 저장 키 (`todoApp.v1`)와 저장 형식 | 같음 | 같음 |
| 마크업 | 같음 | 같음 |
| CSS | 900px 이상에서 2단으로 바꾸는 규칙이 있음 | 그 규칙만 뺐음 |
| 탭 제목 | 할 일 관리 | 할 일 관리 (모바일) |

그래서 기능을 고칠 때는 두 파일의 `<script>`를 똑같이 고쳐야 한다.

### 두 버전이 같은 할 일을 보여 주는 이유

브라우저는 **오리진(origin)** 단위로 사이트를 나눈다. 오리진은 주소 가운데 `프로토콜 + 호스트 + 포트`까지만 본 것이고, 그 뒤의 경로는 따지지 않는다. localStorage도 오리진마다 따로 있어서, 오리진이 같은 페이지끼리만 데이터를 함께 쓰고 다른 오리진의 데이터는 읽을 수 없다.

| 주소 | 오리진 |
|---|---|
| `https://asy0528.github.io/Study02_ToDoList/` | `https://asy0528.github.io` |
| `https://asy0528.github.io/Study02_ToDoList/mobile/` | `https://asy0528.github.io` (경로만 다르므로 같은 오리진) |
| 내 컴퓨터의 `index.html` (`file://…`) | 웹 주소와 다른 오리진 |

- 두 웹 버전은 오리진이 같아서 같은 localStorage를 쓰고, 저장 키도 `todoApp.v1`로 같다. 그래서 모바일 버전에서 적은 할 일이 기본 버전에도 그대로 보인다(배포 주소에서 확인함).
- 같은 이유로 `asy0528.github.io` 아래에 올린 다른 프로젝트도 이 저장 공간을 함께 쓴다. 저장 키를 앱 이름이 들어간 `todoApp.v1`로 정해 두어 다른 앱과 섞이지 않는다.
- 웹에서 연 앱과 내 컴퓨터 파일로 연 앱은 오리진이 달라 할 일을 공유하지 않는다.
- 다른 브라우저나 다른 PC에서 열면 빈 목록으로 시작하고, 브라우저의 사이트 데이터를 지우면 할 일도 함께 지워진다.

## 확인한 것

- PRD 10장 완료 기준 1~8을 모두 확인했다.
- 배포된 주소에서 할 일 추가, 체크, 진행률 막대(위 표의 값), 새로고침 후 유지를 직접 확인했다.
- 폭 360px 화면과 넓은 화면(2단) 모두 가로 스크롤 없이 보이는 것을 확인했다.
- 넓은 화면의 사이드바에서 날짜와 필터 탭이 한 줄에 들어가는 것을 확인했다.
- 모바일 버전은 넓은 화면에서도 한 줄로 보이고, 기능 코드(`<script>`)가 기본 버전과 같으며, 두 버전이 같은 할 일을 보여 주는 것을 확인했다.
- `index.html`을 더블클릭(`file://`)해서 열어도 동작하는 것을 확인했다.

## 이 프로젝트에 대해

AI 코딩 도구로 앱을 만드는 과정을 익히기 위한 두 번째 실습이다. Claude Code에 [Superpowers](https://github.com/obra/superpowers) 플러그인을 붙여, 질문에 답하며 요구사항을 좁히고(brainstorming) 그 결과를 PRD로 남겼다. 그다음 `writing-plans` 스킬로 PRD를 5단계 구현 프롬프트([PROMPTS.md](PROMPTS.md))로 나누고, 단계마다 테스트를 먼저 쓰고 구현하는 방식으로 앱을 완성했다. 배포한 뒤에는 색, 넓은 화면 2단 배치, 최근 항목을 위로 올리는 순서를 다듬었다. 마지막으로 넓은 화면의 사이드바를 카드로 다듬고, 휴대폰용 한 줄 화면은 `mobile/` 버전으로 따로 남겼다.
