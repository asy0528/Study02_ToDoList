# 할 일 관리 앱 구현 프롬프트 (5단계)

[PRD](../../PRD.md)를 Claude Code에 단계별로 넣을 수 있게 나눈 프롬프트다.

## 쓰는 법

- 단계 순서대로 하나씩 붙여 넣는다. 앞 단계의 확인 항목이 모두 통과한 뒤에 다음 단계로 넘어간다.
- 각 프롬프트는 앞 대화를 기억하지 못해도 동작하도록 썼다. 새 세션에서 시작해도 된다.
- 단계마다 끝나면 커밋해 두면, 문제가 생겼을 때 그 단계로 돌아가기 쉽다.

| 단계 | 만드는 것 | PRD 기능 | 확인하는 완료 기준 |
|---|---|---|---|
| 1 | 화면 뼈대, 날짜·저장 함수, 상태 | F-9 | 깨진 데이터 처리 |
| 2 | 추가, 목록 그리기, 완료 체크, 진행률 | F-1, F-2, F-6 | 1, 2, 6 |
| 3 | 수정, 삭제 | F-3, F-4 | 4, 5 |
| 4 | 필터, 날짜 이동, 오늘로 옮기기, 빈 상태 | F-5, F-7, F-8 | 3, 7, 8 |
| 5 | 스타일 마무리, 전체 검증, README 갱신 | 전체 | 1 ~ 8 전체 |

## 모든 단계에 공통으로 적용되는 규칙

각 프롬프트 안에 이미 들어 있다. 따로 붙여 넣을 필요는 없다.

- 작업 전에 PRD를 읽는다.
- 이번 단계 범위만 만든다. 다음 단계 기능을 미리 만들지 않는다.
- `index.html` 파일 하나. 외부 라이브러리, 프레임워크, ES 모듈, 빌드 도구를 쓰지 않는다.
- 사용자 입력은 `textContent`나 `value`로만 넣는다. `innerHTML`에 넣지 않는다.
- 데이터를 바꾸는 동작은 `배열 변경 → commit() → 저장 → render()` 순서를 지킨다.
- PRD의 "이번 버전에서 하지 않을 것"에 있는 기능은 넣지 않는다.
- 끝나면 바꾼 내용과 확인 결과를 보고한다. 직접 확인하지 못한 항목은 확인하지 못했다고 밝힌다.

## 1단계. 화면 뼈대와 데이터 기반

```text
PRD.md 를 먼저 끝까지 읽어 줘.
이 PRD로 할 일 관리 앱을 5단계에 나눠 만들 거야. 지금은 1단계야.

## 목표
화면 뼈대와, 이후 모든 기능이 기댈 날짜·저장·상태 코드를 만든다.
아직 사용자가 쓸 수 있는 기능은 없어도 된다.

## 지시 사항
1. 프로젝트 루트에 index.html 파일 하나를 만든다. <style>과 <script>를 같은 파일 안에 둔다.
   <script type="module">, import/export, 외부 라이브러리는 쓰지 않는다.
2. PRD 6장 화면 설계대로 고정 마크업을 만든다.
   - 헤더: 앱 제목, ◀ 버튼, 날짜 표시 영역, ▶ 버튼, [오늘] 버튼, 진행률 막대와 숫자 영역
   - 입력줄: <form> 안에 텍스트 입력, 카테고리 <select>(업무/개인/공부, 기본값 업무), [추가] 버튼
   - 필터 탭: [전체] [업무] [개인] [공부] 버튼 (data-filter 속성)
   - 빈 <ul> 목록, 빈 상태 안내 문구 영역
   - 모든 입력과 아이콘 버튼에 aria-label을 붙인다.
3. 스타일은 최소한만: 최대 폭 640px, 가운데 정렬, 시스템 글꼴. 꾸미기는 5단계에서 한다.
4. <script>에 PRD 7장 순서대로 다음을 만든다.
   - 상수: STORAGE_KEY = "todoApp.v1", 카테고리 표기(work=업무, personal=개인, study=공부), 요일 이름
   - 날짜 함수: todayString(), addDays(date, n), formatDate(date)
     · 로컬 연·월·일로 "YYYY-MM-DD"를 만든다. toISOString()은 쓰지 않는다 (UTC라 한국 오전 9시 전에 하루가 밀림)
     · addDays는 new Date(y, m - 1, d + n)으로 계산해 월말·연말을 넘긴다
     · formatDate는 "2026-10-02 (금)" 형식
   - 저장 함수: loadTasks(), saveTasks()
     · 저장 형식은 PRD 5장의 { version: 1, tasks: [...] }
     · 값이 없거나, JSON 파싱이 실패하거나, tasks가 배열이 아니면 빈 배열로 시작한다
   - 상태: state = { tasks, selectedDate, filter: "all", editingId: null }
   - commit(): saveTasks() 후 render()
   - render(): 지금은 헤더의 날짜 표시만 갱신해도 된다
   - init(): loadTasks → selectedDate를 오늘로 → render
5. 할 일 추가, 체크, 수정, 삭제, 필터, 날짜 이동 기능은 아직 만들지 않는다.

## 완료 확인
- index.html을 브라우저로 열면 화면 뼈대가 보이고 헤더에 오늘 날짜와 요일이 나온다.
- 개발자 도구 콘솔에 오류가 없다.
- 콘솔에서 확인:
  · addDays("2026-01-31", 1) → "2026-02-01"
  · addDays("2026-12-31", 1) → "2027-01-01"
  · addDays("2026-03-01", -1) → "2026-02-28"
- localStorage["todoApp.v1"]에 "abc"처럼 깨진 값을 넣고 새로고침해도 오류 없이 열린다.

끝나면 만든 내용과 위 확인 결과를 항목별로 보고해 줘.
```

## 2단계. 추가, 목록, 완료 체크, 진행률

```text
PRD.md 와 현재 index.html을 먼저 읽어 줘.
5단계 중 2단계야. 1단계에서 화면 뼈대, 날짜·저장 함수, state, commit(), init()을 만들어 두었어.

## 목표
할 일을 적고, 목록으로 보고, 체크하면 진행률이 올라가는 핵심 흐름을 완성한다.
대상 PRD 기능: F-1 추가, F-2 완료 체크, F-6 진행률, F-9 저장과 복원

## 지시 사항
1. addTask(text, category)
   - 앞뒤 공백을 잘라 내고, 비어 있으면 아무것도 하지 않는다.
   - id는 Date.now().toString(36) + "-" + Math.random().toString(36).slice(2, 8). crypto.randomUUID()는 쓰지 않는다.
   - date는 state.selectedDate, done은 false, createdAt은 Date.now()
   - state.tasks에 넣고 commit()
2. <form>의 submit 이벤트로 추가를 처리한다 (버튼과 Enter가 같은 경로).
   기본 동작을 막고, 추가 후 입력창을 비우고 포커스를 유지한다. 카테고리 선택값은 그대로 둔다.
   빈 입력이면 등록하지 않고 포커스만 유지한다.
3. toggleTask(id): done을 반전하고 commit()
4. getVisibleTasks(): date가 state.selectedDate인 항목을 createdAt 오름차순으로 돌려준다.
   필터 조건도 함수 안에 넣어 두되, 필터 탭 동작은 4단계에서 연결한다.
5. getProgress(tasks): { done, total, percent }. total이 0이면 percent는 0, 아니면 Math.round(done / total * 100)
6. render()를 renderHeader()와 renderList()로 나눈다.
   - renderHeader: 날짜, 진행률 막대 width(%), "완료 수 / 전체 수 (퍼센트)" 텍스트
   - renderList: <ul>을 비우고 getVisibleTasks()로 <li>를 새로 만든다.
     각 줄은 체크박스(data-action="toggle"), 텍스트, 카테고리 배지, [수정]·[삭제] 버튼(아직 동작 안 함)
     <li>에 data-id, 완료 항목에는 done 클래스를 붙인다.
     텍스트는 반드시 textContent로 넣는다.
7. 목록 이벤트는 <ul> 하나에 위임해서 받는다. 항목마다 이벤트를 붙이지 않는다.
8. 완료 항목은 취소선과 흐린 색으로 보이게 한다.
9. 수정, 삭제, 필터, 날짜 이동은 아직 만들지 않는다.

## 완료 확인 (PRD 10장 기준)
- 기준 1: 할 일 3개 추가 → 새로고침 → 3개가 그대로 있다.
- 기준 2: 4개 중 1개 체크 → "1 / 4 (25%)", 막대 4분의 1. 체크 해제 → "0 / 4 (0%)"
- 기준 6: 빈칸, 공백만 입력하고 추가 → 아무 일도 일어나지 않는다.
- 항목이 0개일 때 "0 / 0 (0%)", 막대는 비어 있다.
- <b>굵게</b> 를 입력하면 태그가 아니라 글자 그대로 보인다.

끝나면 바꾼 내용과 위 확인 결과를 항목별로 보고해 줘.
```

## 3단계. 수정과 삭제

```text
PRD.md 와 현재 index.html을 먼저 읽어 줘.
5단계 중 3단계야. 추가, 목록, 완료 체크, 진행률은 이미 동작해.

## 목표
목록의 [수정]과 [삭제] 버튼을 동작하게 만든다.
대상 PRD 기능: F-3 할 일 수정, F-4 할 일 삭제

## 지시 사항
1. 편집 상태는 state.editingId 하나로 관리한다. 한 번에 한 줄만 편집 상태가 된다.
2. [수정] 클릭 → editingId를 그 항목 id로 바꾸고 render()만 한다 (저장하지 않음).
   다른 줄이 편집 중이었다면 그 편집은 저장 없이 닫힌다.
3. renderList에서 editingId와 같은 줄은 편집 모드로 그린다.
   - 텍스트와 배지 자리에 텍스트 입력(현재 값)과 카테고리 <select>(현재 값)
   - [수정]·[삭제] 대신 [저장](data-action="save")·[취소](data-action="cancel")
   - 그린 직후 텍스트 입력에 포커스
4. updateTask(id, text, category)
   - 앞뒤 공백을 잘라 내고, 비어 있으면 저장하지 않고 편집 상태를 유지한다.
   - 아니면 text와 category를 바꾸고 editingId = null, commit()
5. 편집 입력에서 Enter는 저장, Esc는 취소. keydown도 <ul>에 위임해서 받는다.
6. [취소] 또는 Esc → editingId = null, render()
7. [삭제] → confirm("삭제할까요?"). 확인한 경우에만 deleteTask(id) → commit()
   되돌리기 기능은 만들지 않는다.
8. 필터, 날짜 이동, 오늘로 옮기기는 아직 만들지 않는다.

## 완료 확인 (PRD 10장 기준)
- 기준 4: 한 항목의 텍스트와 카테고리를 함께 바꿔 저장 → 목록과 배지에 반영, 새로고침해도 유지.
  다른 항목을 편집하다 Esc → 원래대로.
- 기준 5: 삭제 확인 창에서 취소 → 남는다. 확인 → 사라지고 새로고침해도 없다.
- 편집 중 텍스트를 모두 지우고 Enter → 저장되지 않고 편집 상태 유지.
- A를 편집하다가 B의 [수정]을 누르면 A는 원래 값으로 돌아가고 B만 편집 상태다.
- 2단계 확인 항목(추가, 체크, 진행률, 새로고침 유지)이 여전히 통과한다.

끝나면 바꾼 내용과 위 확인 결과를 항목별로 보고해 줘.
```

## 4단계. 필터, 날짜 이동, 오늘로 옮기기

```text
PRD.md 와 현재 index.html을 먼저 읽어 줘.
5단계 중 4단계야. 추가, 목록, 체크, 진행률, 수정, 삭제는 이미 동작해.

## 목표
카테고리별로 걸러 보고, 날짜를 오가며, 못 끝낸 일을 오늘로 옮길 수 있게 한다.
대상 PRD 기능: F-5 카테고리와 필터, F-7 날짜 이동, F-8 오늘로 옮기기

## 지시 사항
1. 필터 탭 클릭 → state.filter를 data-filter 값으로 바꾸고, editingId = null, render()
   - getVisibleTasks()가 날짜와 필터를 함께 적용하는지 확인한다.
   - 진행률은 getVisibleTasks() 결과로 계산한다 (보고 있는 날짜 + 선택한 필터 기준).
   - renderFilters()를 만들어 선택된 탭에 active 클래스와 aria-pressed="true"를 준다.
   - 필터는 저장하지 않는다. 앱을 열면 항상 전체.
2. 날짜 이동
   - ◀ / ▶ → selectedDate = addDays(selectedDate, ∓1), editingId = null, render()
   - [오늘] → selectedDate = todayString(), editingId = null, render()
   - 이 동작들은 저장하지 않는다 (commit이 아니라 render만).
   - 앱을 켜 둔 채 자정이 지나도 selectedDate를 자동으로 바꾸지 않는다.
3. 오늘로 옮기기
   - task.date < todayString() 이고 !task.done 인 줄에만 [오늘로] 버튼(data-action="move-today")을 그린다.
   - moveToToday(id): date만 todayString()으로 바꾸고 commit(). text, category, done, createdAt은 그대로.
4. 빈 상태 안내 문구 (getVisibleTasks() 결과가 0개일 때)
   - 전체 탭: "이 날의 할 일이 없습니다. 위에서 추가해 보세요."
   - 카테고리 탭: "이 카테고리에는 할 일이 없습니다."
5. 새로 추가하는 할 일은 지금 보고 있는 날짜(selectedDate)에 들어가는지 확인한다.

## 완료 확인 (PRD 10장 기준)
- 기준 3: 업무 3개(1개 완료), 개인 2개(2개 완료) →
  [전체] "3 / 5 (60%)", [업무] "1 / 3 (33%)", [개인] "2 / 2 (100%)", [공부] "0 / 0 (0%)"
- 기준 7: ◀로 어제 → 2개 추가, 1개 체크 → 미완료 항목에만 [오늘로] →
  누르면 어제 목록에서 사라지고, [오늘]을 누르면 오늘 목록에 있다.
- 기준 8: 할 일이 없는 날짜 → 전체용 안내 문구. 항목이 있어도 비어 있는 카테고리 탭 → 카테고리용 안내 문구.
- 오늘이나 미래 날짜에는 [오늘로] 버튼이 없다.
- 새로고침하면 필터는 전체, 날짜는 오늘로 돌아온다.
- 2·3단계 확인 항목이 여전히 통과한다.

끝나면 바꾼 내용과 위 확인 결과를 항목별로 보고해 줘.
```

## 5단계. 마무리와 전체 검증

```text
PRD.md 와 현재 index.html을 먼저 읽어 줘.
5단계 중 마지막 단계야. PRD의 모든 기능이 들어가 있어.

## 목표
화면을 PRD 6장대로 다듬고, PRD 10장 완료 기준 8개를 모두 확인해 앱을 완성한다.
새 기능은 추가하지 않는다.

## 지시 사항
1. 스타일 다듬기 (PRD 6장)
   - 최대 폭 640px, 가운데 정렬, 시스템 글꼴
   - 배지 색: 업무 파랑, 개인 초록, 공부 주황
   - 선택된 필터 탭은 배경색으로 강조
   - 완료 항목: 취소선, 흐린 글자
   - 진행률 막대: 회색 바탕 위 채움 막대
   - 긴 텍스트는 overflow-wrap: anywhere 로 줄바꿈
   - 폭 360px에서도 가로 스크롤이 생기지 않게
2. 접근성 점검
   - 모든 입력과 버튼에 이름(텍스트 또는 aria-label)이 있는지
   - 마우스 없이 Tab, Enter, Space, Esc만으로 모든 기능을 쓸 수 있는지
   - 키보드 포커스가 눈에 보이는지
3. 코드 점검
   - innerHTML에 사용자 입력이 들어가는 곳이 없는지
   - 데이터를 바꾸는 모든 동작이 commit()을 거치는지
   - 쓰이지 않는 함수나 변수, 디버그용 console.log가 남아 있지 않은지
   - PRD의 "이번 버전에서 하지 않을 것" 기능이 들어가 있지 않은지
4. PRD 10장 완료 기준 1~8을 처음부터 순서대로 모두 확인한다.
```
